# keylogger.js

A Node.js native addon that reports keyboard press and release events while
another application is focused — built for push-to-talk, global hotkeys, and
similar actions.

**This package observes every key in the user's session.** It only works
after the user grants the OS-level permission described below, and it must
not be used for covert capture. If that is not what your app does, do not
ship this package.

## Install

```sh
npm install keylogger.js
```

Prebuilt binaries are included for the supported platforms, so no compiler is
needed. If no prebuild matches your platform, install falls back to compiling
with `node-gyp` (which needs a C++ toolchain, and on Linux the `libevdev`
development headers, e.g. `sudo apt-get install libevdev-dev`).

## Usage

CommonJS:

```js
const keylogger = require("keylogger.js");

keylogger.start((event) => {
  if (event.code === "Space" && event.state === "down" && !event.repeat) {
    console.log("push-to-talk key pressed");
  }
});

// later
keylogger.stop();
```

TypeScript (with `esModuleInterop`):

```ts
import keylogger from "keylogger.js";
```

or without it:

```ts
import keylogger = require("keylogger.js");
```

## Events

The callback receives one `KeyEvent` object:

| Field    | Type              | Meaning                                                                 |
| -------- | ----------------- | ----------------------------------------------------------------------- |
| `key`    | `string`          | [UI Events `KeyboardEvent.key`](https://www.w3.org/TR/uievents-key/). Space is `" "` (U+0020). On Linux this is the unshifted US-layout value. |
| `code`   | `string`          | [UI Events `KeyboardEvent.code`](https://www.w3.org/TR/uievents-code/) — the physical key, the same string on every OS. `""` for an unrecognized key. |
| `state`  | `"down" \| "up"`  | `"down"` on press, `"up"` on release.                                    |
| `repeat` | `boolean`         | `true` when an autorepeat `"down"` is generated by holding the key.      |

Use `code` for shortcuts (`"KeyV"`, `"ControlLeft"`, `"Space"`) — it does not
change with the keyboard layout. Use `key` when you want the character the
user typed, after layout translation (macOS and Windows translate with the
active layout and modifier state; Linux has no layout information at the
evdev level, so `key` is the unshifted US value).

## Platforms and permissions

| OS      | Mechanism                        | Permission required                                                                 |
| ------- | -------------------------------- | ----------------------------------------------------------------------------------- |
| macOS   | listen-only `CGEventTap`         | Assistive access: grant the app Accessibility / Input Monitoring in System Settings. |
| Windows | per-user `WH_KEYBOARD_LL` hook   | None beyond the user session. The hook is always removed on `stop()`. (Before 1.0, a slow callback could make Windows silently remove the hook; the callback now runs off the hook thread.) |
| Linux   | read-only `libevdev` on `/dev/input/event*` | The user must be in group `input` (or have an equivalent ACL on the device nodes). Works under X11 and Wayland because evdev sits below the display server. |

On Linux, add the user to the `input` group and log out and back in:

```sh
sudo usermod -aG input "$USER"
```

Note that upstream systemd puts input nodes in group `input` and does not
grant keyboard `uaccess` to the session, so this step is expected on most
distributions.

## Failure

`start` throws a JavaScript error instead of failing silently:

- `TypeError` if the callback is missing or not a function.
- `Error` if called while already listening — call `stop()` first.
- `Error` if the OS listener could not be installed. The message names the
  permission: assistive access on macOS, the failed hook on Windows, or group
  `input` on Linux.

`stop()` is always safe: it is a no-op when not listening, and it removes the
hook / event tap / device reads and frees the native resources.

## Limits

- One listener per process.
- Keyboard only — no mouse or other devices.
- Listen-only: keys are never swallowed, rewritten, or injected. macOS uses a
  listen-only event tap (falling back to a default tap only if creation
  fails), Windows always calls `CallNextHookEx`, Linux only reads.
- No promise API; events go to the callback you pass to `start`.
- Linux `key` values are the unshifted US layout (no layout translation).
- On Windows, `key` for printable keys is layout-translated but does not apply
  Shift state (Shift+1 reports `key: "1"`); `code` is unaffected.
- Holding a key down produces `"down"` events with `repeat: true`.

## Support matrix

- Node.js `>=22` (CI tests Node 22 and 24).
- macOS 11+ (x64, arm64), Windows 10+ (x64), Linux with libevdev (x64, arm64).
- The exact architectures shipped are the prebuilds in the published tarball;
  other platforms compile from source at install time.
